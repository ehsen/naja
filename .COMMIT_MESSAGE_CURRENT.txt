## Summary

This commit completes two major tasks:

### 1. Exception Language Compliance (100% - 26/26 Tests)
Fixed all remaining exception handling issues to achieve full compliance:
- Fixed `TypeSystem.CreateDotNet` to use proper `BindingFlags.Instance` and bind overloaded constructors
- Fixed exception subclass hierarchy detection in `ClassDeclaration.cs` with `autoExceptionCtor`
- Fixed exception variable scoping with `DeletedSentinel` in exception handler cleanup
- Added thread-local assembly tracking in `TypeSystem` to fix isinstance() with user-defined exception classes
- Added NameError generation when accessing deleted exception variables

**Result**: All 26 exception tests now pass, including:
- Try/except/else/finally chains
- Exception chaining (raise...from)
- Custom exception hierarchies
- Exception variable scoping (PEP 3110)
- Bare except clauses

### 2. NajaBuiltins.cs Refactoring - Elimination of Direct References
Removed ALL direct `typeof(NajaBuiltins).GetMethod(...)` calls throughout the codebase:

**Changes**:
- Updated `NajaBuiltinsMethodCache.cs` with two new entries:
  - `AddEventHandler_Method` → `ReflectionHelpers`
  - `RemoveEventHandler_Method` → `ReflectionHelpers`
  
- Fixed all IL emission sites to use `NajaBuiltinsMethodCache`:
  - `CallEmitters.cs` (3 references: ToStr, CreateDotNet)
  - `AttributeEmitters.cs` (GetStaticAttr)
  - `AssignmentEmitters.cs` (AddEventHandler/RemoveEventHandler)
  - `AssemblyEmitter.ClassBody.cs` (IteratorMoveNext)
  - `StatementEmitter.cs` (UnpackIterable)

- Updated runtime method lookup in `ReflectionHelpers.DynamicCall` to search specialist classes
  (StringFunctions, Collections) instead of NajaBuiltins

- Replaced assembly anchor in `AssemblyPEWriter.cs` from NajaBuiltins to DynamicOperators

- Removed `using static Naja.CodeGen.NajaBuiltins` from `TypeMapper.cs`
